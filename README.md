# Маршрут — приложение торгового представителя

Веб-приложение для телефона: маршрут на день, точки и долги из МойСклад, остатки и цены по складу, заказ покупателя прямо в МойСклад, отметка визита с комментарием и фото. Для руководителя — планирование маршрутов по дням недели и отчёт за день.

## Из чего состоит

| Файл | Что это | Куда положить |
|---|---|---|
| `docs/index.html`, `docs/report.js`, `docs/manifest.json`, `docs/icon.svg` | само приложение и отчёт по брендам | папка `docs` репозитория — её публикует GitHub Pages |
| `Code.gs` | серверная часть: ходит в МойСклад, пишет в Google Таблицу | Apps Script внутри Google Таблицы |

Напрямую из браузера в МойСклад обращаться нельзя: токен пришлось бы положить в страницу, и его увидел бы любой. Поэтому токен хранится только в Apps Script.

## Установка (около 20 минут)

### 1. Токен МойСклад

МойСклад → Настройки → Пользователи → нужный пользователь → «Доступ к API» → создать токен. У пользователя должны быть права на контрагентов, товары, **остатки**, заказы покупателей и отчёт «Взаиморасчёты». Лучше завести для этого отдельного пользователя, а не использовать администратора.

### 2. Google Таблица и скрипт

1. Создайте новую Google Таблицу.
2. Расширения → Apps Script. Удалите содержимое и вставьте `Code.gs`.
3. Настройки проекта (шестерёнка) → Свойства скрипта → добавьте `MS_TOKEN` с токеном из шага 1.
4. Выберите функцию `setup` и нажмите «Выполнить». Google попросит доступ к таблице, Диску (для фото) и внешним запросам — разрешите. В таблице появятся листы «Сотрудники», «Маршруты», «План дня», «Визиты», «Координаты».
5. Выполните функцию `testMoySklad` и откройте журнал: там должны быть ваши склады, типы цен, юрлицо и число точек. Если ошибка — в журнале написано, что не так.

### 3. Сотрудники

Лист «Сотрудники»:

| Ключ | Имя | Роль | Склады | Активен |
|---|---|---|---|---|
| (сгенерирован) | Руководитель | руководитель | | да |
| (сгенерирован) | Иванов Иван | торговый | Основной склад | да |

- **Ключ** — пароль сотрудника в ссылке. Для нового сотрудника придумайте длинную случайную строку (16+ символов).
- **Склады** — название склада точно как в МойСклад. Торговый видит остатки только этого склада. Если указать несколько через `;`, в заказе появится выбор склада.
- У руководителя склады можно не указывать — тогда доступны все.
- Чтобы закрыть доступ, поставьте «нет» в «Активен».

### 4. Публикация скрипта

Apps Script → Развернуть → Новое развёртывание → тип «Веб-приложение» → выполнять от имени «Я», доступ «Все». Скопируйте ссылку, она заканчивается на `/exec`.

После любого изменения `Code.gs`: Развернуть → Управление развёртываниями → карандаш → версия «Новая» → Развернуть. Ссылка при этом не меняется.

### 5. Сайт

1. В `index.html` найдите строку `var API_URL = '';` и вставьте ссылку из шага 4.
2. Загрузите `index.html`, `report.js`, `manifest.json`, `icon.svg` в репозиторий, включите GitHub Pages.
3. Раздайте ссылки вида `https://salesdsvolga.github.io/<репозиторий>/?key=<ключ сотрудника>`.

Сотрудник открывает ссылку один раз, ключ запоминается. На iPhone: Safari → «Поделиться» → «На экран Домой». На Android: Chrome → меню → «Добавить на главный экран».

## Дополнительные настройки (свойства скрипта)

| Свойство | Зачем |
|---|---|
| `ORG_NAME` | От какого юрлица создавать заказы. Пусто — первое в списке. |
| `DEFAULT_PRICE_TYPE` | Тип цены, если в карточке точки он не задан. Пусто — первый тип цены. |
| `POINT_TAG` | Брать только контрагентов с этой группой (например, `точки`), чтобы в список не попали поставщики. |
| `RESERVE` | `да` — заказ сразу резервирует товар на складе. |
| `SHOW_ZERO` | `да` — показывать позиции с нулевым остатком. |
| `DEBT_POSITIVE` | `да` — если у вас долг покупателя отображается положительным балансом. |
| `TZ` | Часовой пояс, по умолчанию `Europe/Samara`. |

## Как это работает

- **Точки** — контрагенты МойСклад (не из архива). Обновляются раз в 15 минут.
- **Долг** — отрицательный баланс контрагента из отчёта «Взаиморасчёты». Проверьте на одной знакомой точке; если знак обратный — включите `DEBT_POSITIVE`.
- **Цена** — по типу цены из карточки контрагента. Если для этого типа у товара цена не заполнена, берётся цена по умолчанию. Цену считает сервер, с телефона её подменить нельзя.
- **Остатки** — по складу сотрудника, обновляются раз в 3 минуты. «Доступно» — остаток минус резерв. Каталог (названия и цены) обновляется раз в 30 минут.
- **Заказ** — создаётся в МойСклад как «Заказ покупателя» с точкой, складом и комментарием «Заказ из приложения, торговый: …». Повторное нажатие при плохой связи второй заказ не создаёт.
- **Маршрут** — руководитель задаёт точки по дням недели во вкладке «Планирование». Торговый может на конкретный день добавить, убрать или переставить точки — постоянный маршрут при этом не меняется.
- **«Порядок по карте»** — расставляет непосещённые точки по принципу «каждый раз ближайшая» от текущего местоположения. Координаты точек определяются по адресу из МойСклад автоматически и сохраняются на листе «Координаты»; если точка определилась неверно, поправьте широту и долготу там вручную.
- **«В Яндекс Картах»** — открывает маршрут по непосещённым точкам (Яндекс принимает до 10 точек за раз).
- **Визит** — результат, комментарий и до 4 фото. Строка пишется на лист «Визиты», фото — в папку «Фото визитов (торговые)» на Google Диске владельца таблицы.

## Отчёт «Деус · Хулиган · Бланш · Нуар» (вкладка «Бренды»)

Тот же отчёт, что раньше собирался генератором из двух выгрузок, только данные скрипт берёт из МойСклад сам. Выгружать файлы больше не нужно.

**Откуда берутся данные** — так же, как в сохранённых фильтрах «Для генератора 2» и «долги»:

| | Раньше (вручную) | Теперь (скрипт) |
|---|---|---|
| Продажи | Заказы покупателей, период с 01.01, канал продаж «Деус», печать по шаблону | те же заказы через API: товар, группа товара, цена × кол-во, контрагент, доп. поле «Адрес - Куда доставить», дата |
| Долги | Отгрузки с 01.08, канал «Деус», без группы контрагентов «хп», строки где оплачено меньше суммы | те же отгрузки через API с тем же условием |

**Обновление.** Раз в час по расписанию (включается функцией `setup`; если скрипт уже был установлен — один раз запустите `installReportTrigger`). Руководитель может обновить сразу кнопкой «Обновить из МойСклад». Собранный отчёт хранится на листе «Отчёт (данные)» — его не нужно открывать и править.

**Первый запуск.** Выполните функцию `syncReport` вручную и посмотрите, нет ли ошибки. Затем сверьте вкладку «Бренды» с последним отчётом из генератора: число точек, суммы по брендам за месяц, число долгов.

**Настройки отчёта (свойства скрипта):**

| Свойство | По умолчанию | Зачем |
|---|---|---|
| `REPORT_CHANNEL` | `Деус` | канал продаж |
| `REPORT_FROM` | 1 января текущего года | с какой даты брать заказы, формат `2026-01-01` |
| `REPORT_SKIP_AGENTS` | пусто | контрагенты, которых не брать в продажи: точные названия через `;` |
| `REPORT_DEBT_FROM` | `2026-08-01` | с какой даты брать отгрузки для долгов |
| `REPORT_DEBT_SKIP_TAG` | `хп` | группа контрагентов, которую не брать в долги |
| `REPORT_ADDR_ATTR` | `Адрес - Куда доставить` | доп. поле заказа с адресом точки |
| `REPORT_FOR_REPS` | `да` | `нет` — отчёт видит только руководитель |

Бренды и ароматы для мониторинга (Tokyo Spring, Black Currant) заданы в `Code.gs` в списках `BRANDS_DEF` и `AROMAS_DEF` — новый аромат добавляется одной строкой.

Кнопка «Скачать HTML» сохраняет отчёт таким же файлом, какой делал генератор, — его можно переслать как раньше.

## Ограничения

- Без интернета приложение не работает. Корзина при этом не теряется — она хранится в телефоне до отправки.
- Скидки МойСклад (персональные, накопительные) не применяются — только типы цен.
- Местоположение сотрудника при визите не записывается.
- Google ограничивает определение координат по адресу примерно тысячей запросов в сутки; за один запрос маршрута определяется не больше 15 новых точек.
- Старый способ получения остатков МойСклад отключает в 2027 году; приложение уже использует новый (ассортимент без остатков + краткий отчёт об остатках).

## Демо-режим

Пока в `index.html` не вставлена ссылка, или если добавить к адресу `?demo=1`, приложение показывает выдуманные данные и ничего никуда не отправляет. `?demo=manager` — то же для роли руководителя.
